Vocabulary and Anki design decisions
====================================

Extended article schema
-----------------------

- `word` is the canonical key for either a word or a phrase; legacy `entry`
  input is rejected.
- The article-level `image_prompt` illustrates the word card.
- Each meaning's image prompt is `meaning.example.image_prompt`, beside its
  Spanish phrase, English translation, and optional usage comment.
- `ArticleExtended` rejects unknown fields so prompt/model/generator drift is
  detected. `ArticleExtendedCollection` manages the JSON cache.

Media and Anki
--------------

- TTS and images are generated through the provider factory, never through
  inline backend copies in the Anki script.
- Kokoro's Spanish defaults are language code `e`, voice `ef_dora`, 24 kHz
  audio, 0.3 seconds of silence at both ends, and MP3 output.
- Generated audio/images use deterministic collision-resistant names under
  ignored `cache/audio` and `cache/images` directories.
- Anki model/deck IDs remain stable. Word and meaning notes use deterministic,
  namespaced GUIDs so rebuilding updates existing notes instead of duplicating
  them.
- A word article produces one word note plus one note for each meaning. Every
  note references its corresponding cached image and audio file.
- `preview` renders `templates/word_card.html` without loading media or Anki
  backends; `build` generates/reuses media and writes the `.apkg`.

Per-topic Markdown remains the responsibility of `ArticleShort`, the topic
scanner, and the maintained inbox cleaner; no duplicate collection layer is
introduced.
