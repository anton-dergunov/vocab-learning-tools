Extended vocabulary article design
==================================

Canonical schema decisions
--------------------------

- `word` is the canonical key for either a single word or a phrase. The old
  experimental `entry` key is intentionally unsupported.
- An article-level `image_prompt` describes the word card.
- Each meaning has one `example`; the example owns its `image_prompt` because
  that image illustrates the example sentence. A meaning-level `image_prompt`
  is intentionally unsupported.
- Unknown JSON fields are rejected so prompt, sample, model, and generator
  schema drift is detected immediately.

Canonical shape
---------------

{
  "word": "añorar",
  "translation": "to yearn for",
  "image_prompt": "Prompt for the word card, with no text",
  "meanings": [
    {
      "meaning": "To miss something deeply",
      "example": {
        "spanish_phrase": "Añoro mi hogar.",
        "english_translation": "I miss my home.",
        "image_prompt": "Prompt illustrating the example, with no text",
        "comment": "Optional usage nuance"
      }
    }
  ],
  "notes": ["Usage, register, synonyms, and contrasts."]
}

Implemented responsibilities
----------------------------

- `ArticleExtended`, `ArticleMeaning`, and `ArticleExample` validate and
  serialize the JSON format using Pydantic v2.
- `ArticleExtendedCollection` manages `cache/vocabulary/<word>.json` files.
- `MediaCollection` manages generated image or audio cache directories.
- Per-topic Markdown remains the responsibility of `ArticleShort`, the topic
  scanner, and the maintained inbox cleaner; no duplicate collection layer is
  introduced.
- The Anki prompt, `input.json`, templates, and draft generator use this same
  canonical schema.
